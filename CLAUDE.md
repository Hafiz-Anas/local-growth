## Project

Local Growth Engine — Instagram growth/management app for local businesses (Raid Technologies). Next.js 16 + PostgreSQL/Prisma + Auth.js; every screen reads and writes through the JSON API with TanStack Query. Instagram data, AI generation, email and file storage sit behind swappable service interfaces with mock/local implementations until those integrations land. See README.md for setup and the real-vs-mocked list.

## Commands

- `npm run db:up` — start PostgreSQL (docker-compose.yml); `cp .env.example .env` first
- `npm run db:migrate` — apply/create migrations (`prisma migrate dev`); `npm run db:seed` — wipe + seed demo data; `npm run db:reset` — both
- `npm run dev` — dev server (http://localhost:3000)
- `npm run build` / `npm start` — production build / serve
- `npm run lint` — ESLint (flat config, includes React Compiler rules such as `react-hooks/set-state-in-effect`)
- `npx tsc --noEmit` — typecheck. Run `npx next typegen` first on a fresh clone; `LayoutProps` / `PageProps` globals are generated.
- Prisma 7: client is generated to `lib/generated/prisma` (gitignored; `postinstall` runs `prisma generate`), CLI config in `prisma.config.ts`, connection via `@prisma/adapter-pg`. Import the client from `@/lib/db` only.
- `npm run test:e2e` — Playwright (`tests/e2e/*.spec.ts`) against a RUNNING local app on a seeded throwaway DB (`E2E_BASE_URL`, `E2E_BROWSER_CHANNEL=chrome`; see `playwright.config.ts`). Refuses non-local URLs.
- `npm test` — node:test + tsx over `tests/**/*.test.ts` (Meta mapping/client tests against `tests/meta/fixtures.json`). Test modules import only pure code (no `server-only`, no db).

## Architecture

**Data flow.** Server pages in `app/` only guard (`requireFeature()` / `requireAdmin()`, → `notFound()`/redirect) and render a client `*View` from `components/<feature>/`. Views load data with the hooks in `lib/api/queries.ts` (user screens) and `lib/api/admin.ts` (admin), each with an Instagram-style skeleton, `ErrorState` and `EmptyState` (`components/shared/states.tsx`). The (user) layout renders the business view model (`getClientView()`, `lib/server/client-view.ts`) into `ActiveClientProvider`; after changing the business itself (photo, Instagram connection) call `router.refresh()`. Nothing under `app/`, `components/` or `lib/api` may import `/mock-data` — only the mock services and the seed do.

**Auth.** Auth.js v5 (`auth.ts` at the root): Credentials provider + bcryptjs, JWT session in an httpOnly cookie. Session claims (`role`, `businessId`, `name`, `avatarUrl`, effective `features`, `sessionVersion`) live in the JWT. On **every** request the `jwt` callback runs `checkSession` (`lib/auth/claims.ts`, one PK lookup): deleted/suspended users and tokens whose `sessionVersion` differs are signed out; claims reload when `User.updatedAt` or `Business.permissionsUpdatedAt` is newer than the token (5-min safety refresh otherwise). Any code that changes a business's `FeaturePermission` rows must bump `permissionsUpdatedAt` (`lib/server/permissions.ts` does); any password change must go through `setPassword()` (`lib/server/passwords.ts`), which bumps `sessionVersion`. `authorize()` rate-limits failed logins (5 / 15 min per IP + email) through the `RateLimiter` interface (`getRateLimiter()` in `lib/server/rate-limit.ts`, in-memory; `RATE_LIMIT_STORE` selects the implementation) and throws `CredentialsSignin` subclasses whose `code` the login form shows. `lib/auth/actions.ts`: login, logout, start/exit admin preview. Password reset: `lib/server/password-reset.ts` + `app/api/password-reset/{request,confirm}` (SHA-256-hashed single-use token, 1 h), link sent via `EmailService` (`lib/services/email.ts`). Demo logins live in `config/demo.ts` (used by the seed and the login page).

**API (`app/api`).** Every route is wrapped in `handler()` (`lib/server/http.ts`): JSON envelope `{ ok: true, data }` / `{ ok: false, error: { code, message, details? } }`, `ApiError` for expected failures, Zod via `readJson` / `readQuery` / `readParams`. Guards in `lib/server/guards.ts`: `requireAuth`, `requireRole("ADMIN" | "USER")`, `requireBusiness`, `requireFeature(...keys)` / `requireAnyFeature` / `assertFeature` — a disabled feature is **404**, never 403. The businessId always comes from the session (or an admin route param), never from the body; lookups by id use `where: { id, businessId }` so other businesses' rows are 404. Queries use the explicit `*_SELECT` constants + mappers in `lib/server/dto.ts` so hashes/tokens are never loaded. Business-scoped reads live in `lib/server/data.ts` (shared by user routes and `/api/admin/preview/:id`); log changes with `logActivity()`. Response types: `types/api.ts`. Browser calls: `apiFetch` (`lib/api/client.ts`).

**Services (`lib/services`).** Interfaces with env-selected implementations: `InstagramService` — chosen **per connection** (`InstagramConnection.provider`, routed in `getInstagramService()`): `MockInstagramService` serves the mock packs by business id; `MetaInstagramService` (`lib/services/instagram.meta.ts`) reads data synced into the DB by `lib/server/instagram-sync.ts` and calls Meta live only for replies, business discovery and publishing (single image: `lib/server/publishing.ts` claims the ScheduledPost → JPEG copy via `lib/services/images/instagram-fit.ts` → `lib/services/meta/publish.ts` container + status poll + publish; triggers are the "Publish now" routes and `GET /api/cron/publish` with `CRON_SECRET`; failures are `PublishReason` codes → 422 `publish_failed`, kept on `ScheduledPost.failureReason` / `PostDraft.publishError`). Instagram DMs arrive at `/api/webhooks/instagram` (GET handshake with `META_WEBHOOK_VERIFY_TOKEN`; POST verified with `X-Hub-Signature-256` + `META_APP_SECRET`, 200 at once, work in `after()`): `lib/server/instagram-dm.ts` finds the business by `igAccountKey` (mock: `igUserId`), respects `engagement.aiReplies`, stores `InstagramDirectMessage` and keeps one PENDING `ReplyDraft` (channel `DM`) per conversation; approval sends via `replyToMessage` (`lib/services/meta/messaging.ts`, `POST /me/messages`), 24-hour window → `EXPIRED` / `dm_window_closed`; `npm run simulate-dm` signs a fake webhook for local testing. Keyword replies (`engagement.dmRules`, `EngagementRule` + `KeywordReplyTrigger`): the same webhook's `comments` changes, with the sync as fallback, go through `lib/server/keyword-replies.ts` (pure matching/decision in `lib/keyword-replies.ts`): the trigger row (unique per comment) is the dedupe claim, 24-hour per-person cooldown, public reply via `replyToComment` + private DM via `sendPrivateReply` (`recipient: { comment_id }`), approval-mode rules create a `ReplyDraft` with `ruleId`/`privateReply`; reply drafts are gated per kind (`replyKinds` in `lib/server/replies.ts`); `npm run simulate-comment`. `INSTAGRAM_PROVIDER` (`mock`|`meta`) only picks the flow for new connections (`connectFlow()`, `lib/services/meta/config.ts`). Pure Meta code lives in `lib/services/meta/` (config, Graph client with appsecret_proof + usage headers + backoff, error classification, mappers, endpoint functions — tested in `tests/meta/`); Facebook Login is `lib/server/meta-connect.ts` + `app/api/integrations/instagram/*`; per-business Graph clients (`graphFor`, `lib/server/meta-client.ts`) log failures to `IntegrationEvent` and flag the connection (190 → `NEEDS_RECONNECT`, permission → `missingPermissions`). Map service errors with `instagramApiError()` (`lib/server/instagram-errors.ts`). Write calls need a connection → `instagram_not_connected`; `AIService` (`lib/services/ai.ts`, `AI_PROVIDER` `mock`|`gemini`; mock fills caption templates from `catalog.ts`; `GeminiAIService` never fails — on any error it returns the mock's text and logs the reason to IntegrationEvent (provider "gemini", call `ai.*`); every prompt is in `lib/services/text/prompts.ts`, pure client/parsing/request gate (`GEMINI_TEXT_RPM` 12/min, `GEMINI_TEXT_RPD` 450/day per instance — over budget → template text, logged once; pauses after quota/key errors) in `lib/services/text/`, tested in `tests/gemini/text.test.ts`), `ImageService` (`lib/services/image.ts`, `IMAGE_PROVIDER` `mock`|`gemini`; pure Gemini client, error classification, prompt builder and mock PNG in `lib/services/images/`, tested in `tests/gemini/` with recorded fixtures — never call Google in tests; `GEMINI_API_BASE` points the client at a local stub) — Post Generator draft images (`lib/server/post-images.ts`: generate / upload / remove, one image per draft, `PostDraft.imageSource` GENERATED gets the "AI-generated image" label, failures are `image_unavailable` with a reason, logged to IntegrationEvent with provider "gemini"); `StorageService` (`STORAGE_PROVIDER`: `local` disk in `UPLOAD_DIR`, served by `/api/uploads/[...key]`; `vercel-blob` = `lib/services/blob-storage.ts`, pure with an injected Blob client, tested in `tests/storage/`; shared contract in `storage-core.ts`), `EmailService` (`EMAIL_PROVIDER` `console`|`resend`; pure templates (HTML + text, EN/AR by the user's saved language, RTL) and the Resend client with an injected HTTP client in `lib/services/mail/`, tested in `tests/email/` — never call Resend in tests; `RESEND_API_BASE` points it at a local stub). Every send failure is an `EmailSendError` (logged without secrets), which `handler()` maps to 503 `email_unavailable`; sign-up and the onboarding invite catch it and carry on. Email links are built from `AUTH_URL` (`appBaseUrl`). The Post Generator's product catalogue comes from `catalog.ts` (mock). Instagram tokens are AES-256-GCM encrypted (`lib/crypto.ts`); `getInstagramAccount()` decrypts server-side only.

**Self-onboarding.** `/signup` (server action `signupAction` → `lib/server/signup.ts`) creates a USER + Business (`source SELF_SIGNUP`, `onboardingStatus IN_PROGRESS`, plan from `SystemSetting "selfSignupPlan"`, `lib/server/settings.ts`) and sends a verification link (`lib/server/email-verification.ts`, `/verify-email`). Admin-created users get `emailVerifiedAt` set at creation. The (user) layout redirects IN_PROGRESS businesses to `/onboarding` (full-screen wizard, `components/onboarding/`); `Business.onboardingStep` (1–7, `config/onboarding.ts` → `ONBOARDING_STEPS`; Connect Instagram is step 1, business details step 2 — reordering steps needs a data migration of the stored numbers) is the resume point, moved only via `POST /api/onboarding/progress` (`moveToStep` checks the current step is complete). Every move/error writes an `OnboardingEvent` (`recordEvent`/`recordError` in `lib/server/onboarding.ts`) — add one when you add a new failure path in the wizard. The posting language (`Business.languages`, default both) is not asked: `buildBrandContext` infers it from the captions (`lib/brand-language.ts`) while onboarding is in progress; afterwards it is edited in Settings → Brand profile. Brand data: `BrandPost` (5 in onboarding, 12 max), basics on Business (`brandColors`, `logoUrl`) + BrandVoice (`toneLevel`, `brandWords` = words to use, `wordsToAvoid`), and versioned `BrandContext` (`lib/server/brand.ts`; the current one is the newest READY version; edits sync back to basics). Brand components in `components/brand/` use plain `useMutation` (the wizard has no ActiveClientProvider) and take `readOnly` for preview/admin. Competitors keep non-ready handles with `validationStatus`; Competitor Insights only lists READY ones.

**AI assistant.** Feature module `assistant` (ON in every plan; migration `20261014150000_assistant_feature` turned it on for existing businesses). `/assistant` (nav "AI Assistant"; on phones a header icon, the tab bar is full) renders `AssistantChat` (`components/assistant/assistant-chat.tsx`, self-contained so it can move into a drawer/sheet later). Modes post / analytics / competitors (`assistantModes()`: competitors only with the `competitors` feature). `lib/server/assistant.ts` gathers the grounding data per question (stored Instagram data via `InstagramService`, brand profile, READY competitors; demo/mock data and stale Meta data are labelled, no Instagram data when not connected); `lib/services/text/assistant.ts` (pure) computes the derived numbers and formats the data block, the wording is `assistantPrompt` in `prompts.ts`; the call is `AIService.chat()` through the same request gate as captions — it never falls back to template text: failures are 503 `assistant_unavailable` (details reason) and nothing is saved. History: `AssistantConversation` / `AssistantMessage` per business (only answered turns), last 12 messages sent as chat turns; `DELETE /api/assistant/conversations/:id` removes a chat; `ASSISTANT_DAILY_QUESTIONS` (40 per business per 24 h) → 429 `assistant_limit`. Not shown in admin preview.

**AI recommendations.** Feature module `recommendations` (ON in every plan; migration `20261014160000_recommendations` turned it on for existing businesses). `/recommendations` (`components/recommendations/`): 3–5 actions per analysis, each with EN+AR text, confidence (strong / moderate / early, capped in code by `based_on_posts`: <5 → early, <10 → at most moderate) and the posts it rests on. `lib/server/recommendations.ts`: the analysis reads `gatherAssistantFacts(…, "strategy")` (the assistant's data block with everything, incl. weekday figures), skips the AI when `strategyInputHash` (data by the day + past decisions + `STRATEGY_PROMPT_VERSION`) matches the last run (an `unchanged` run), and stores `RecommendationRun` + `Recommendation`. Owner decisions (accepted / dismissed / done, undo to new) are fed into the next prompt; Done stores a 14-day baseline and after 7 days `compareOutcome` (pure, `lib/services/text/strategy.ts`) stores up / down / no clear change / not enough data. Weekly: `GET /api/cron/recommendations` (`CRON_SECRET`, daily in `vercel.json`, `RECOMMENDATIONS_CRON_BATCH` AI analyses per run) analyses businesses whose last run is ≥ 7 days old and checks due outcomes; manual Refresh: 3 AI analyses per business per 24 h → 429 `recommendations_limit`; AI failure → 503 `recommendations_unavailable`, nothing changes; no Instagram data → 409 `instagram_not_connected`. Cron routes share `assertCronAuthorized` (`lib/server/cron.ts`).

**Roles & proxy.** `proxy.ts` wraps Auth.js `auth()`. Logged-out → `/login` (public: `/login`, `/signup`, `/forgot-password`, `/reset-password`; `/verify-email` works either way); users can't open `/admin/*`; admins are sent to `/admin` unless the `lge_preview` cookie is set ("Preview as this client"), in which case user routes render that client.

**Feature permissions.** `config/features.ts` is the single catalogue (`FEATURE_KEYS`, `FEATURE_MODULES`). Keys are `module` or `module.sub`; a sub-feature is effective only if its module is ON (`isFeatureEnabled` in `lib/permissions`). Plan presets are in `config/plans.ts` (UI uses lowercase `starter`/`admin`; the DB enums are uppercase — map at the boundary). OFF features must be **removed, never grayed out**:
- nav: `filterNav()` over `config/navigation.ts` (`feature` on each item)
- widgets: `<Feature flag>` / `useFeature()`
- routes: `await requireFeature(flag)` in the server page → `notFound()` (rendered by `app/(user)/not-found.tsx`)
- storage: one `FeaturePermission` row per (business, key); the session carries effective keys; the user layout builds the nav on the server and passes `permissions` to `ActiveClientProvider`

**Client state.** Server state lives in the TanStack Query cache (keys in `qk`, `lib/api/queries.ts`); mutations update it optimistically where it feels instant (reply approve/dismiss, rule toggles, permission toggles, removals) and roll back on error. User-screen mutations go through `useAction()`, which turns every action into a read-only notice during admin preview; in preview the data hooks read `/api/admin/preview/:id` instead of the user APIs. Failed mutations are reported centrally by `QueryProvider` via `reportError()` (`lib/api/errors.ts`): friendly localized `errors.<code>` toasts, the Connect Instagram dialog for `instagram_not_connected`, and a redirect to `/login?expired=1` on any 401 (`lib/api/client.ts`); pass `meta: { handlesErrors: true }` when a form shows its own errors. Toasts/prompt state: `store/ui-store.ts` (`notify.*`). Theme is **dark by default**: only an explicit "light" is light (the old "system" value reads as dark, `normalizeTheme` in `lib/theme-script.ts`); the `lge_theme` cookie (set at login and on every toggle) drives the server-rendered `<html class>` and `THEME_INIT_SCRIPT` before first paint. Theme, language and sidebar state sync to `User.uiPreferences` through `PreferencesSync` (mounted in both shells); the login action sets the locale cookie from the saved language. Zustand selectors must not return fresh objects (`?? []` inside a selector causes an infinite render loop) — default outside the selector.

**i18n / RTL.** All UI copy is in `locales/en.json` + `locales/ar.json` (keep keys in sync), read via `useI18n().t("a.b", { var })`. Locale lives in the `lge_locale` cookie; the root layout sets `<html lang dir>`. Use logical properties (`ms-`, `pe-`, `start-`, `text-start`) and `<bdi>` for user content inside UI strings. Mock *content* (captions, comments) stays in its original language.

## Design system

Instagram-native look. All tokens live in `app/globals.css`: raw `--lge-*` variables (light on `:root`, dark on `.dark`), mapped in `@theme inline` to utilities such as `bg-background`, `text-muted`, `border-border`, `bg-primary` (#0095F6), `text-body` (14px) / `text-caption` (12px) / `text-title` / `text-heading`, `rounded-card` / `rounded-button` / `rounded-panel` / `rounded-pill`, `bg-ig-gradient`, `text-ig-gradient`. Use tokens, not raw hex. Keep the Instagram gradient to accents only. If you add a custom token, also register it in the `extendTailwindMerge` config in `lib/utils.ts`; otherwise `cn()` drops conflicting classes (e.g. `text-body` would remove `text-primary`).

**Avatars.** Every avatar goes through `components/shared/avatar.tsx` (`src` + initials/tone fallback when the image is missing or fails). Entities carry `avatarUrl` (`User`, `Client`, `Competitor`, `IncomingComment.authorAvatarUrl`). Images are local SVGs in `public/avatars/`, generated by `node scripts/generate-avatars.mjs` (brand marks and abstract silhouettes — no photos of real people, no hotlinking).

**Sidebar collapse.** State lives on `<html data-sidebar="collapsed">`, set before paint by `SIDEBAR_INIT_SCRIPT` (`lib/sidebar-script.ts`) from localStorage. Style widths/fades with the `sidebar-collapsed:` variant (e.g. `xl:sidebar-collapsed:w-…`); use `lib/sidebar.ts` hooks only for JS concerns such as tooltips. Below 1280px the rail is always collapsed; below 768px the bottom tab bar replaces it. The Next dev badge is disabled in `next.config.ts` because it covered the sidebar profile row.

`components/ui/` holds shadcn-style primitives on the unified `radix-ui` package, restyled. `components/shared/` holds the Instagram composites (`PostPreview`, `CommentRow`, `MetricCard`, `StatTile`, `FeatureToggle`, `ClientRow`, `Avatar` with story ring, `MediaPlaceholder` for mock imagery). Icons: lucide-react, 24px outline.
